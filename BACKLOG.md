# Backlog

Ordered roughly by priority. Items marked *(final review)* came out of the pre-merge whole-branch review; *(spec §11)* are the roadmap items deferred from the original design.

1. **Refine the filter presets.** What each story means is settled and written down in docs/shoe-stories.md; this item is the implementation. Drop wide-toebox as a preset, add Race, and drop the two-year recency default from every preset. Needs three things the app lacks: a **not-carbon** plate token (Easy excludes carbon but must keep the nylon-plated daily trainers, which today's `none`/`plated`/`carbon` vocabulary cannot express), a fleet percentile helper for the price cap computed at click time, and a weight bound for Tempo — the one threshold still undecided, because energy return and price alone leak ordinary daily trainers. Numbers are a starting point to tune after real use, not a final answer. The `pace` fact is a good sanity check against a candidate threshold set, but it is one editor's label and never the filter (docs/scraping.md §Editorial facts).
2. **UX polish.** Once the flow is right, the small stuff earns its keep. Nothing here is a defect; it is the difference between a tool that works and one that is pleasant. Known candidates: the loading state is a bare line of text and the first paint has no skeleton, so a slow fetch looks broken; lazy-loaded row images shift the layout as they arrive; the mobile filter drawer appears and disappears with no transition or focus handling; the empty state says only that nothing matched, without offering the loosest bound to relax; expandable rows signal it with a cursor change alone. Specifics should be gathered from using the tool rather than listed up front. **Do this together with the accessibility item below** — both touch every component, and doing them separately means editing the same files twice.
3. **Harvest the option-typed tests.** `tongue-gusset-type` and `heel-tab` are populated on nearly every shoe page but are never fetched, so they drop out as empty (docs/scraping.md §Empty tests). The details crawl already has the page; reading them there costs no requests. Needs a home for non-numeric per-shoe readings, which the app has no column type for today.
4. **CSV date-precision column.** *(final review)* `shoes.csv` and the in-app export emit year-derived dates with nothing marking them imprecise; add a `preciseReleaseDate` column (schema addition — semantics in docs/scraping.md §Release-year supplement).
5. **Back/forward navigation.** `popstate` is unhandled, so Back doesn't restore the previous view. Must be worked through against docs/app.md §View and URL ownership rather than around it.
6. **Accessibility polish.** Mobile filter drawer has no focus trap/Escape handling; range inputs all announce as "min"/"max" without their metric name; expanded rows lack `aria-controls`. Pairs with the UX polish item above; land them together.
7. **Head-to-head compare view.** *(spec §11)* Select 2–4 shoes for a side-by-side metric comparison.
8. **Other categories.** *(spec §11)* Trail/hiking/sneakers — the pipeline is parameterised by seed shoe already; needs a category switcher in the UI and per-category datasets. Each details record already carries the per-shoe `categorySlug` this would key on (docs/scraping.md §Non-running shoes), which currently only ever excludes.
9. **Price/deal tracking.** *(spec §11)* MSRP history is implicit in git history of `data/`; surface it.
10. **Public refresh trigger.** *(spec §11)* Currently refresh buttons need repo access; an issue-ops trigger would let friends request one.
