# Backlog

Ordered roughly by priority. Items marked *(final review)* came out of the pre-merge whole-branch review; *(spec §11)* are the roadmap items deferred from the original design.

1. **Tune the preset thresholds against real use.** Easy, Tempo and Race are implemented to the reasoning in docs/shoe-stories.md, and the numbers are a starting point rather than a final answer. Tempo is the least settled: both its bounds are percentiles of the live fleet — weight at the 40th, energy return at the 50th — and each is a guess at what "light" and "lively" mean. Score any candidate change the way docs/shoe-stories.md §Checking a threshold set describes — apply the thresholds and look at what fraction of the shortlist carries the `pace` label you would expect. The `pace` fact is one editor's label and never the filter (docs/scraping.md §Editorial facts).
2. **Surface imprecise release dates in the app.** *(usability review, 2026-07-28)* Only 24 of 450 shoes carry a real release date; the other 426 are stamped 1 January (docs/scraping.md §Release-year supplement). So the "2y" chip drops 119 of the 120 shoes released in 2024, and any date bound silently drops the 17 shoes with no date at all — while the receipt reports "0 outside your bounds", because its accounting covers range filters only. This is the honesty problem the tool exists to solve, in the one filter that does not participate in it. Either extend the receipt to non-range filters or mark imprecise dates in the table; ideally both. Note there is also no "released before" bound, so the last-generation strategy in docs/shoe-stories.md cannot be expressed at all.
3. **UX polish.** Once the flow is right, the small stuff earns its keep. Nothing here is a defect; it is the difference between a tool that works and one that is pleasant. *(usability review, 2026-07-28 — found by driving the real UI, ordered by how badly each misleads.)* **Sticky table headers**: the default view is a 25,000 px page and `thead` is static, so ten columns of bare numbers scroll headerless, taking the sort controls with them. **Brand counts ignore every other filter**: with `disc=only` active the list still reads "adidas (55)" and ticking it yields 23 — every coverage bar beside it is computed over the filtered population by design, so this is the one number that reads as a promise it does not keep; also ~50 brands in a 230 px alphabetical box with no search. **Preset meaning is hover-only**: cards show "Easy / 150 shoes" and the explanation is a `title`, which does not exist on mobile, where the cards fill the first screen. **No column carries units or a direction**, so "Width / Fit 93.7" says nothing about whether more is better. **Only one shoe detail opens at a time**, and expansion is not in the URL. **No share affordance** despite shareable URLs being a stated goal, and Export CSV emits only the visible columns with no link back to RunRepeat. Plus: the loading state has no skeleton so a slow fetch looks broken; lazy-loaded row images shift the layout; the mobile drawer has no transition; the empty state does not say which bound to relax; expandable rows signal it with a cursor change alone. **Do this together with the accessibility item below** — both touch every component, and doing them separately means editing the same files twice.
4. **Harvest the option-typed tests.** `tongue-gusset-type` and `heel-tab` are populated on nearly every shoe page but are never fetched, so they drop out as empty (docs/scraping.md §Empty tests). The details crawl already has the page; reading them there costs no requests. Needs a home for non-numeric per-shoe readings, which the app has no column type for today.
5. **CSV date-precision column.** *(final review)* `shoes.csv` and the in-app export emit year-derived dates with nothing marking them imprecise; add a `preciseReleaseDate` column (schema addition — semantics in docs/scraping.md §Release-year supplement).
6. **Back/forward navigation.** `popstate` is unhandled, so Back doesn't restore the previous view. Must be worked through against docs/app.md §View and URL ownership rather than around it.
7. **Accessibility polish.** Mobile filter drawer has no focus trap/Escape handling; range inputs all announce as "min"/"max" without their metric name; expanded rows lack `aria-controls`. *(usability review, 2026-07-28)* Add: every `role="radiogroup"` — strike, discontinued, generation pickers — makes each radio its own tab stop and ignores arrow keys, which is the interaction the role promises; a roving tabindex fixes all of them at once. And it is 49 tab stops from the top of the page to the first table row, with no skip link. Pairs with the UX polish item above; land them together.
8. **Head-to-head compare view.** *(spec §11)* Select 2–4 shoes for a side-by-side metric comparison.
9. **Other categories.** *(spec §11)* Trail/hiking/sneakers — the pipeline is parameterised by seed shoe already; needs a category switcher in the UI and per-category datasets. Each details record already carries the per-shoe `categorySlug` this would key on (docs/scraping.md §Non-running shoes), which currently only ever excludes.
10. **Price/deal tracking.** *(spec §11)* MSRP history is implicit in git history of `data/`; surface it.
11. **Public refresh trigger.** *(spec §11)* Currently refresh buttons need repo access; an issue-ops trigger would let friends request one.
